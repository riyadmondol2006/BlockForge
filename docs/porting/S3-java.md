# S3: Chunker `conversion/encoding/java/**` survey (read-only)

Root: `cli/src/main/java/com/hivemc/chunker/conversion/encoding/java/` ("J/" below). 297 files, 28,960 raw lines (about 17k code lines).
No data files: every table is Java source. Resources are only `java/CavesAndCliffsHeightPack.zip` (datapack, 36K total) and `java/default_font_width_codepoints.json` (FontUtil, sign text width; low value).
Shared code NOT in this area but required: `encoding/base/resolver/{identifier,entity,blockentity,itemstack}` (BlockMapping/ItemMapping/StateMappingGroup/TypeMapping/EntityResolver/KeyedHierarchyBasedResolver), `intermediate/**` (ChunkerVanillaBlockType, VanillaBlockStates, Palette*, ChunkerLevelSettings), `nbt/Tag` (gzip/zlib/LZ4 NBT IO), `JsonTextUtil`.

## 1. Composition: inheritance chain, not flags
`JavaEncoders` = `TreeMap<JavaDataVersion, (readerCtor, writerCtor)>`; `getNearestEncoder` = `floorEntry(dataVersion)`. 21 encoders registered for 66 registered JavaDataVersions. No encoder is needed for every version, only where the *format* changes.
Reader: `createReader(dir)` -> `JavaDataVersion.detect(dir)` -> floor encoder -> `ctor(dir, dataVersion.getVersion(), converter)`.
Writer: `getNearestVersion(requestedVersion)` (floor by Version) -> floor encoder. The `Version` passed to resolvers is the *rounded-down registered* version (e.g. 1.20.1), so all `version.isGreaterThanOrEqual(...)` table gates use the exact patch version.

Each encoder vN has 4 reader classes + 4 writer classes: LevelReader/WorldReader/ColumnReader/ChunkReader and LevelWriter/WorldWriter/ColumnWriter/ChunkWriter. Each extends the SAME class of the previous vN (fully qualified, so `v1_20.reader.ColumnReader extends v1_19_3.reader.ColumnReader`). Most are empty boilerplate that only re-points `createWorldReader / createColumnReader / createChunkReader / createWorldWriter / createColumnWriter / createChunkWriter` factories to the vN subclass (~2.7k raw lines for all versioned packages, ~95% boilerplate).
Chain (reader and writer identical): `Java{Level,World,Column,Chunk}{Reader,Writer}` (base = Anvil 1.8.8, DataVersion 0) <- v1_11 <- v1_13 <- v1_14 <- v1_15 <- v1_16 <- v1_17 <- v1_18 <- v1_19_3 <- v1_20 <- v1_20_3 <- v1_20_5 <- v1_21 <- v1_21_2 <- v1_21_4 <- v1_21_6 <- v1_21_9 <- v1_21_11 <- v26_1 <- v26_2 <- v26_3. Worlds 1.9-1.10 use base (floor to V1_8_8); 1.12.x uses v1_11.
`JavaReaderWriter.buildResolvers()` (interface default, overridden with `super.buildResolvers(c).xxx(...)` per version) returns a `JavaResolversBuilder`; the base default is the fully LEGACY resolver set; later versions swap individual resolvers. This is the second inheritance axis (resolvers); `JavaResolversBuilder.build()` makes an anonymous `JavaResolvers` that wires nbt-block -> block-identifier -> (legacy id <-> string id) and holds one `dataVersion`.

## 2. DataVersion handling
`JavaDataVersion`: static list of 66 (dataVersion int, Version) pairs, two TreeMaps (by int, by Version). `LAST_ANVIL_FILE_VERSION = 19133`. Includes release builds only (1.9 = 169 ... 26.3 = 5017); snapshots round down.
`detect(dir)`: gunzip `level.dat`; if no `Version` compound -> accept only if `version == 19133` and treat as DV 0 (1.8.8); else use `Version.Id`. All `Tag.read*JavaNBT` helpers (gzip/zlib/raw/lz4, level.dat, chunks, maps, player files) AUTO-UNWRAP a root child compound named `data` then `Data` (else return root), so every `level.getXxx` above operates on the inner `Data` compound. Writer writes `{"Data": data}` with `Version{Id,Name,Snapshot=0}`, `version=19133`, `DataVersion`, `initialized=1`, `LastPlayed=now`, fixes `SpawnY==32767 -> -1`, `GameType>3 -> 3`.
Written everywhere: chunk root `DataVersion`, POI root, entity root, map root, player compound, 26.1 data files.
Unknown (newer than newest) versions floor to latest; older than 1.8.8 impossible (oldest=V1_8_8).

## 3. Region / Anvil
Read (`MCAReader`, `JavaWorldReader`): `region/r.X.Z.mca` (file >= 4096 B, name has 4 dot parts). 4096 B location table: entry i (x = i&31, z = i>>5): 3-byte big-endian sector offset (count byte ignored); offset 0 = empty. Seek `offset*4096`: int length (minus 1 for the type byte), byte type: low 7 bits `0` empty, `1` gzip, `2` zlib (default), `3` raw, `4` LZ4 (1.20.5+, Mojang LZ4 block stream: needs custom decoder), bit 0x80 => data in external `c.<cx>.<cz>.mcc` beside the region (absolute chunk coords). Timestamp table ignored. Decompress is parallel per column.
Dimension discovery: base dir per `JavaLevelDirectoryResolver`: Overworld = world root, Nether `DIM-1`, End `DIM1`, custom `dimensions/<ns>/<key>` (a dir counts only if it has `region/`); sub-dirs `region`, `entities` (>=1.17), `poi`. 26.1+: all dims under `dimensions/minecraft/...`. Players `playerdata/` (26.1: `players/data/`). Maps `data/map_N.dat` + `data/idcounts.dat` (short `map`), 26.1: `data/minecraft/maps/N.dat`.
Column filters: unwrap `Level`; require `xPos`,`zPos` (mismatch only logged); skip if `Status` in {empty, structure_starts, structure_references, biomes, noise, surface, carvers, liquid_carvers, terrain} with or without `minecraft:`.
Write (`JavaWorldWriter.writeMCAData`): always zlib (type 2); append-only: seek to `max(8192,len)`, write len+type+bytes, `setLength` pad to 4096 multiple, patch the location entry (3-byte sector + sector count). Oversize threshold `4096*256` (1 MiB compressed): write whole payload to `c.X.Z.mcc`, region keeps a 1-sector stub (`len=1`, type `0x82`). Timestamps never written. One RandomAccessFile per region kept open and synchronized. POI is written (nether portals only) with the same routine to `poi/`.
Sections (modern): list `sections` (>=1.18) / `Sections`; each needs `Y` (byte, int tolerated) and `size > 1` (empty section skipped). Chunk Y is a signed byte; writer drops nothing for >=1.17, restricts Y 0..15 before.

### Palette bit packing (`util/PaletteUtil`)
- index order i = x | z<<4 | y<<8 (YZX, x fastest) for blocks (dim 16, 4096) and biomes (dim 4, 64). Same ordering as nibble arrays (light/legacy Data).
- bits = max(minBits, ceil(log2(keyCount))) by `while (keyCount > 1<<bits) bits++`; minBits = 4 for blocks, 1 for biomes.
- Pre-1.16 (`...1_13`): SPANNING, i*bits across 64-bit longs, array len = ceil(4096*bits/64). 1.16+ (`...1_16`): NON-spanning, `valuesPerLong = 64/bits`, long index i/valuesPerLong, shift (i%valuesPerLong)*bits, len = ceil(4096/valuesPerLong). The Java uses a MAGIC multiply-shift table to do that division: unnecessary in Rust (`i / vpl`).
- Reader auto-detects by length: if `len != ceil(4096/vpl)` -> spanning with `bits = floor(len*64/4096)`; else 1.16 layout. (Layouts coincide for bits 4, 8, 16, 2, 1.) Reader short-circuits: keys empty -> EmptyPalette; 1 key or missing data -> SingleValue; else ShortBasedPalette[x][y][z].
- Writer: 1.13/1.14/1.15 spanning writer; 1.16+ non-spanning. Blocks always write `data` even for 1 key (zeros); biomes write `data` only when keyCount > 1. An empty chunk writes a 1-entry air palette.
- Block palette key: `{Name, Properties{str->str}}` ( >=26.3 `{id, properties}`; bare string allowed when default state). Property values are NBT strings (`StateValue.fromNBT`).
- 1.18+ location: `sections[i].block_states.{palette,data}`, `sections[i].biomes.{palette,data}`; 1.13-1.17: `Palette`/`BlockStates` in the section itself, no per-section biomes.
- Biome palette min bits 1, dim 4 (4x4x4 cells), list of StringTag; `as4X4Palette(chunkY + (CavesAndCliffs ? 4 : 0))`: intermediate indexes biome sections from y=0, so worlds with min_y -64 offset by 4. Writer pads empty air sections up to biome height (16 sections, or dimension height if CavesAndCliffs) when `shouldPreventYBiomeBlending`.

### Heightmaps / biomes / light
- HeightMap: only <1.13 (`HeightMap` int[256], index `[x][z]`, i&15 = x, i>>4 = z); 1.13+ ignored on read, not written (vanilla recomputes). Writer for <1.13 regenerates with `ColumnUtil.getHighestLitOrSlabBlock` when the intermediate map is not `JavaLegacyHeightMap`.
- Biomes: byte[256] (<=1.12), int[256] (1.13-1.14), int[1024] 4x4x4 cells (1.15-1.17), per-section palette (1.18+). Id<->biome: `JavaBiomeIDResolver` (87 puts, gated 1.9/1.13/1.14/1.16/1.17/1.18) and `JavaNamedBiomeResolver` (67 puts, gated 1.19/1.20/1.21.2/26.2/26.3; custom biome ids pass through if custom identifiers allowed).
- Light: section `BlockLight` / `SkyLight` byte[2048] nibbles (low nibble first, x fastest). Reader only if `shouldProcessLighting`. Writer always writes both (zeros if absent); SkyLight skipped in the Nether. Column flag `LightPopulated` (<1.14) / `isLightOn` (>=1.14).
- Column write extras: `xPos`,`zPos`,`TerrainPopulated=1`, `Status`, `yPos` (>=1.18); NOT written: InhabitedTime, LastUpdate, Heightmaps, structures, block_ticks (vanilla tolerates). Palettes are compacted (`compact(AIR)`) before writing.

## 4. Legacy (< 1.13) numeric-id path
Read (base `JavaChunkReader.readPalette`): `Blocks` byte[4096] (y*256+z*16+x), `Add` nibble (high 4 bits of id, ids > 255), `Data` nibble -> `LegacyIdentifier(id, data)` in a 16^3 ShortBasedPalette -> `resolvers.readBlock(LegacyIdentifier)`: `JavaLegacyBlockIDResolver` (int -> "minecraft:name", 254 entries: 198 base + 16 @1.9, 5 @1.10, 17 @1.11, 18 @1.12) -> `Identifier.fromData(name, data)` -> `JavaLegacyBlockIdentifierResolver` (name + `data` state -> ChunkerBlockType + states) -> intermediate. Write is the reverse: `writeLegacyBlockIdentifier` (identifier + data -> id) with Add nibble.
The legacy name+data mapping uses `BlockMapping.flatten(name, "data", Multimap<Integer,Type>)` (35 uses, e.g. wool 16, log with Axis pair) + `BlockMapping.of(name,"data",n,type)` + `JavaLegacyStateGroups` (65 groups, 27 `multiState("data", [states..], JavaLegacyStateTypes.X)` bit-packed data values; 45 types, 623 mappings; 1 `generate()` loop for vine bits).
Items: `id` may be string or short (1.8-); `JavaLegacyItemIDResolver` 315 numeric ids; `JavaLegacyItemIdentifierResolver` (224 rows: 200 base, 18 @1.9, 3 @1.11, 3 @1.12) + `Damage` short as data. Also legacy IDs: entity type ids (64, spawn egg meta), potion ids (110), effect ids (34), enchant ids (30), map decoration ids, painting motives (26).
Pretransforms (read side only, `JavaLegacyReaderPreTransformManager`, 23 registrations, 10 handlers, ~420 code lines): legacy blocks carry no connection state, so after reading the column the manager computes: chest left/right, tall plants top/bottom, stems attach, tripwire/fences/nether fences/panes/walls/chorus connections, fence gate in-wall, doors halves, stairs shape, redstone wire sides, fire, snowy grass, note block. Writer legacy manager is empty. Modern managers (1.13+) are both empty ("Currently no handlers").
Legacy block entities (`JavaLegacyBlockEntityResolver`, 31 handlers ~1000 code lines): CamelCase ids ("Chest", "Trap", "Airportal", "DLDetector"...), `OLD_TO_NEW_ID` bimap for >=1.11, handlers also split Chest/TrappedChest by block, create BlockEntities from blocks (beds, flower pot, note block, skulls) with `generateBeforeProcess/Write`.

## 5. Resolvers: dispatch
Block entities / entities extend `KeyedHierarchyBasedResolver<R, Key, NBT, Value>`: a handler is `(key, valueClass, ctor)` with `read(resolvers, nbt, value)` / `write(...)`; `register()` order forms a hierarchy via class inheritance (`JavaBlockEntityHandler` base reads/writes `x,y,z`; `JavaContainerBlockEntityHandler` `Items[{Slot,id,...}]`+`CustomName`; `JavaRandomizableContainer` `LootTable/LootTableSeed`). `to(nbt)`: key = lowercase `id` with `minecraft:` prefix (block entity) or `id` through entityTypeResolver (entity); runs handlers parent->child, so subclasses add fields. Unknown -> UnknownBlockEntity/UnknownEntity preserving NBT only if `shouldAllowNBTCopying` (`preserveUnknown*`); otherwise logged missing mapping and dropped. Extra hooks (interfaces): `generateBeforeProcess/Write` (spawn BlockEntity/Entity from blocks, e.g. beds, flower pot), `updateBeforeProcess/Write`, `shouldRemoveBeforeProcess/Write`, `generateFromItemNBT`/`writeToItemNBT` (items carrying block entity data, via components since 1.20.5).
Modern block entity registry (`JavaBlockEntityResolver`): 53 `register(new ...)` lines: 28 real handler classes (2380 raw lines: Skull 265, DecoratedPot 208, Banner 166, Container 142, Campfire 134, Sign 125, Shelf 124, ChiseledBookshelf 124, Structure 120, Randomizable 104, Spawner 95, Furnace/Jigsaw/Brewing/Crafter/Beacon/Bed ~50-60, rest <50) + ~30 `EmptyBlockEntityHandler` (chest, ender chest, hopper, barrel, bell, ...). Gates: 1.14 (campfire, jigsaw, lectern, bell, blast furnace, smoker, barrel), 1.15 beehive, 1.17 sculk sensor, 1.19 catalyst/shrieker, 1.19.3 chiseled bookshelf, 1.19.4 brushable/decorated pot, 1.20 hanging sign/calibrated sensor, 1.20.3 crafter/trial spawner, 1.20.5 vault, 1.21.2 creaking heart, 1.21.9 shelf/copper golem statue, 26.2 potent sulfur/bed (bed block-entity removed).
Entities (`JavaEntityResolver`): only 5 handler classes: JavaEntityHandler (`Pos`,`Motion`,`Rotation`; `id`), Hanging, Painting (`variant`/`facing` >=1.19 else `Motive`/`Facing`), ItemFrame (+Glow via Empty), Cushion (26.3). Everything else = typed `ChunkerEntityType` (string table 180 puts: 76 base + ~104 gated 1.9 ... 26.3) or UnknownEntity with preserved NBT. I.e. mobs/vehicles are NOT semantically converted.
Item stacks: `ItemStackResolver` = property holders: `createPropertyHolder(nbt)` reads `id` (+`Damage` <1.20.5) -> `readItemIdentifier` (item table first, else block table), then ~25 property handlers (`PropertyHandler<T>.read/write` keyed by `ChunkerItemProperty`): amount, durability, display(name/lore/color), enchants/stored enchants, repair cost, can_place_on/can_break, map id+decorations, spawn egg entity, book (title/author/pages JSON), horn, potion, trim, stew, fireworks (+explosion), lodestone, bundle, entity_data, block_entity_data. Three flavors: `JavaLegacyItemStackResolver` (<1.13, `tag` compound, `Count` byte, `Damage` short; 870 raw lines), `JavaItemStackResolver` (1.13-1.20.4, `tag{...}`, 1056 raw), `JavaComponentItemStackResolver` (>=1.20.5, `count` int + `components{"minecraft:..."}`, 1208 raw; 24 component keys). Text uses `util/JsonTextUtil` (outside this dir; switches JSON-string vs NBT text compound at 1.21.5).
Misc small tables (all version-gated puts): effects (40 name/34 id), enchantments (44/30), potion types 46 (+110 legacy ids), banner patterns 43 + 41 short names, trim patterns 18, trim materials 11, horn instruments 8, map decorations 16 (+10 ids), painting motives 51 (+26 legacy), map colors 64 base RGBA + shade multipliers (map colour byte = base*4+shade; nearest-colour search on write).

## 6. level.dat / player / dimensions
Reader (`JavaLevelReader`): tasks parseLevelSettings (+player), parseMaps, parsePOI -> `ChunkerLevel`. Settings are read by `ChunkerLevelSettings.fromNBT` which is annotation driven: 64 fields tagged `@Java("path")` such as `GameRules.doFireTick` (note: in `Data` compound, rule values are STRINGS "true"/"false"), `Difficulty`, `allowCommands`; special cases via `readCustomLevelSetting(root, settings, name, type)` hook: `RandomSeed` (<1.16 `RandomSeed` long; >=1.16 `WorldGenSettings.seed`), generator type (<1.13 `generatorName` default/flat + `generatorOptions` string, voidness check `startsWith("3;minecraft:air;127;")`; 1.13-1.15 flat layers compound; >=1.16 `WorldGenSettings.dimensions.minecraft:overworld.generator.{type,settings.layers}`; sets MapFeatures/bonusChestEnabled), CavesAndCliffs (1.17 datapack probe, >=1.18 true), R20Support/R21Support/Drops (DataPacks.Enabled contains "update_1_20"/"update_1_21"/"winter_drop" during experimental windows, true when built-in), FlatWorldVersion (0 <1.17 else 1).
Player: `Player` compound in level.dat (<26.1) with `Pos`, `Motion`, `Rotation`, `Inventory[{Slot,...}]`, `equipment{offhand,feet,legs,chest,head}` (1.21.5+, slots -106,100..103), `Dimension` (int <1.16, string >=1.16), `playerGameType`. Writer mirrors (clamps gameType 5 -> level type, >3 -> 3; `splitEquipment` at >=1.21.5). Other `playerdata/*.dat` are NOT converted (only the single-player entry).
POI (read): `poi/*.mca`, sections `Records[type=minecraft:nether_portal,pos]` -> portal clusters (adjacent by Manhattan <=2) -> ChunkerPortal. Writer regenerates POI records for nether portal blocks (`free_tickets=0`). Everything else (other POI types) discarded.
Maps: `map_N.dat` `{data:{colors byte[16384], scale, dimension, xCenter, zCenter, width, height, unlimitedTracking, locked}}` IDs renumbered 0.. on write.
Dimension writes: world gen defaults when not copying NBT: custom generator forced to VOID; noise generator settings per dimension (`createDimension`, biome sources per version).

### Machine-conversion recipe (write once, Python or Rust build.rs)
Input: the 4 files `JavaBlockIdentifierResolver.java`, `JavaItemIdentifierResolver.java`, `legacy/JavaLegacyBlockIdentifierResolver.java`, `legacy/JavaLegacyItemIdentifierResolver.java`, plus `JavaStateGroups/Types` (+Legacy). I already wrote counting scripts at `/tmp/claude-1000/-home-riyadm-Downloads-ABDM-Compressed-ATLauncher-master/1ac3f7c9-6a69-4c57-8abd-9bb7db34c49b/scratchpad/s3/{count.py,triv.py,forms.py,cum.py}` (scratch only, they validate these regexes).
1. Gate tracking: per line `if \(version\.(isGreaterThanOrEqual|isLessThan)\((\d+), (\d+), (\d+)\)\)\s*\{` sets current gate = (a,b,c) and remembers brace depth; track `{`/`}` counts and reset gate to base when depth returns. Only `>=` gates occur in the four identifier files; `JavaBlockEntityResolver` also has one `else`.
2. Row types (apply per line, flat text works because every call is on its own lines):
   - simple: `(register\w*)\((Block|Item)Mapping\.of\("([^"]+)",\s*Chunker\w+\.(\w+)(?:,\s*Java(?:Legacy)?StateGroups\.(\w+))?\)\)` -> (kind=wrapper, id, ENUM, group). Capture the wrapper name as a flag (register, registerOverrideOutput, registerOverrideInput, registerOverrideInputOutput, registerDuplicateInput, registerDuplicateOutput). Covers 660/673 block, 436/552 item, 108/175 legacy block, 197/220 legacy item `of` lines.
   - group: from `\.\s*put\("([^"]+)",\s*Chunker\w+\.(\w+)\)` inside a `*Mapping.group(ImmutableMultimap...` block until `\.build\(\),\s*(Java\w*StateGroups)\.(\w+)\)`; emit each put with that group.
   - state-qualified: `of\("id",\s*"state",\s*(\d+|"[^"]*"),\s*Chunker\w+\.(\w+)(?:,\s*(group))?` (cauldron, prismarine data 1/2, legacy `data` rows).
   - spawn egg: `of\("(..._spawn_egg)",\s*ChunkerVanillaItemType\.SPAWN_EGG,\s*ChunkerItemProperty\.SPAWN_EGG_MOB,\s*ChunkerVanillaEntityType\.(\w+)\)`.
   - legacy `flatten("minecraft:x", "data", [VanillaBlockStates.S,] ImmutableMultimap.<Integer,...>builder().put(N, [Pair.of(Axis.Y, ]ChunkerVanillaBlockType.T[)])...)` -> rows (id, data N, T, optional (state S, value)); 35 occurrences, parse `\.put\((\d+),\s*(?:Pair\.of\((\w+)\.(\w+),\s*)?Chunker\w+\.(\w+)`.
   - state groups: `public static final (Versioned)?StateMappingGroup (\w+) = new ...Builder()` then lines `\.state\("(\w+)",\s*VanillaBlockStates\.(\w+),\s*(\w+)\.(\w+)\)`, `\.defaultOutput\(VanillaBlockStates\.(\w+),\s*(\w+)\.(\w+)\)`, `\.defaultInput\("(\w+)",\s*(\d+)\)`, `\.multiState\("data",\s*List\.of\(([^)]*)\),\s*(\w+)\.(\w+)\)`, `\.version\(new Version\((\d+), (\d+), (\d+)\),` (nested group, 23). Types: `TypeMapping<\w+, (\w+)> (\w+) = new TypeMapping.Builder` then `\.mapping\(("?[\w.]+"?),\s*(?:List\.of\()?([\w., ]+)\)?\)` (multi-value forms exist for legacy: `List.of(Bool.FALSE, FacingDirection.DOWN)`; the single `generate()` loop = vine bits, hand-code).
3. Output data file: `blocks.tsv` columns `java_id  chunker_enum  state_group  since_dataversion  flag` (flag = O/I/IO/DI/DO), `items.tsv` (+ `egg_entity`), `legacy_blocks.tsv` (`name data enum [state=value]`), `state_groups.txt` (one line per prop: `GROUP prop VANILLASTATE TYPE`), `state_types.txt` (`TYPE javaValue enumValue(s)`), `legacy_ids.tsv` (int,name,since). Estimated sizes: blocks ~1.3k rows * ~50 B = 65 KB; items 585 rows 25 KB; state types 545+623 rows 30 KB; all < 200 KB, trivially `include_str!` + parsed at startup (or `phf`/sorted slices via build.rs). Convert the 12 exception rows by keeping the explicit enum column and omitting it when `UPPER(id)` (saves 99% of the column).
4. Because tables map java id -> *Chunker's* ChunkerVanillaBlockType enum names, the generated data is only useful to BlockForge if the intermediate model uses the same canonical block set. If BlockForge's intermediate block is `namespace:name + property map` (Java-flat), skip the enum column entirely and use tables only for (a) since-version filtering, (b) default/dropped states (e.g. `waterlogged=false` default, `BARRIER` waterlogged only >=1.20.2, `BELL powered` >=1.15, BUBBLE_COLUMN defaults), (c) cross-edition canonicalization (grass<->short_grass, chain<->iron_chain, etc.).
Also machine-convertible: the 5 simple name tables via `mapping\.put\((?:Chunker\w+\.\w+\.)?(\w+|"[^"]+"),\s*("?[^")]+"?)\)` (biomes, entities, effects, enchants, potions, banner, trims, horns, motives, legacy id tables) with the same gate regexp; the 64 RGBA `new Color(r,g,b,a)` rows + the three gates (1.8.1 +1, 1.12 +, >1.16.0 +).

## 10. Value-per-effort ranking for milestone 1 (Java 1.20/1.21 <-> intermediate)
1. region.rs + palette.rs + dirs + format thresholds: highest value, ~800 lines, zero table dependency; unlocks reading/writing chunk NBT (can already round-trip Java->Java by block-name palettes).
2. Block table loader + state interpreter (generated from the regex recipe, gated at 1.20.x/1.21.x; only 1006-1099 block ids, 448-494 items needed): the single biggest correctness lever; do it generator-first, never by hand.
3. Chunk reader/writer >=1.18 (sections, block_states, biomes palette, block_entities, entities folder merge/split, Status handling, light arrays, yPos): ~650.
4. level.dat settings + player + dimension dirs for 1.20.x/1.21.0-1.21.8 (flat level.dat, `playerdata/`): ~700. Add 1.21.9 (spawn/border), 1.21.11 (game rules) and 26.1 split as flag branches after.
5. Generic block entity + container + sign + skull + banner + spawner + furnace + lectern + chest family; everything else pass through original NBT when NBT copying allowed: ~600. Entities: generic with NBT copy + painting/item frame: ~250.
6. Item stacks (components format) basic: count, custom_name, lore, enchantments, damage, map_id, potion; the rest later: ~400 of the 700.
7. Biome tables (67 names) and 1.18+ biome 4x4x4 mapping: ~150, depends on intermediate biome model.
8. Maps (colors, decoration), POI portals, Caves&Cliffs/experimental datapack flags (flags do not matter on 1.20+; skip), Writer-side `DragonFight`/`Version` etc: low.
9. LZ4 region compression (only 1.20.5+ worlds that set `region-file-compression=lz4`; default stays zlib; safe to skip, return error).
Defer: legacy (<1.13) stack (3,500 lines, 40% tables), 1.13-1.17 formats, legacy pretransforms, font width util, Caves&Cliffs pack.
Pitfalls to copy deliberately: reader maps unknown blocks to AIR with a "missing mapping" log (no abort); mislocated chunk is only logged; empty sections (size<=1) skipped; writer must set DataVersion on every root and use the 1-sector `.mcc` stub; chunks with UNFINISHED_STATUSES skipped; `Y` byte may be int; waterlogged default false on Java when state missing; written palette min 4 bits (blocks)/1 (biomes); SkyLight omitted in Nether; entity/POI regions are separate files from 1.17.
